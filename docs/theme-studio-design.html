Herdr Theme Studio

A Herdr app mod that turns the app's scattered look settings into one window: theme gallery, every color token, fonts, glass and pane frames. Every change shows in the real window as you make it, because the Studio writes the same files Herdr already redraws from.

What the research found

Two things changed the plan. First, the desktop app has its own mod system, separate from the TUI's herdr-plugin.toml plugins. Mods are JavaScript that describes native GPUI elements. There is no HTML or CSS, so a theme can't be a stylesheet. Second, Herdr already has a complete look system underneath. What's missing is a way to drive it. Herdr's own Settings → Look screen offers only layout and theme picks. Everything else has to be edited by hand in JSON.

On window transparency: GPUI, the UI toolkit Herdr is built on, has a blurred-window mode, and the macOS pieces for it are linked into the Herdr binary. Herdr just has no setting that turns it on. A single root field would expose it, something like "window_background": "blurred". That needs a request to the Herdr maintainers. The Studio can't add it. One is already open: herdr-app#190 proposes window_opacity and window_blur in settings.json, and its author has a draft PR. It also warns that alpha on stacked layout backgrounds adds up to nearly solid, which is why the chrome-opacity slider is in doubt.

Transparency, in three tiers

TIER 1 · REAL

Tinted glass

Terminal opacity below 1 lets the window background show through terminal text: a gradient made from the theme, or any image. Translucent pane frames sit on top. This works everywhere Herdr runs.

TIER 2 · ILLUSION

Frosted wallpaper

The Studio reads the current desktop picture, then blurs and dims it with Core Image through osascript -l JavaScript, which ships with macOS. It saves the result as the window background. It reads as macOS vibrancy, but it shows only your wallpaper, never the windows behind Herdr, and it doesn't shift as you move the window. It rechecks the wallpaper every minute. macOS only; elsewhere this falls back to tier 1.

TIER 3 · NEEDS HERDR

True vibrancy

A real see-through window, blurring whatever is behind it. Herdr would have to expose GPUI's blurred-window mode. The Studio keeps a disabled switch for it that turns on if a future Herdr version adds the field.

How it looks

A working mock: the Studio as a floating, draggable Herdr window over a normal Herdr layout. Switch themes, drag the glass sliders and change the background to see what each knob does. The real thing draws with native GPUI, so expect the same layout with Herdr's own type and spacing.

How it works

themes/studio-*.jsonPalettes

One file per theme the Studio makes or imports. It never edits Herdr's shipped theme files, which Herdr would move aside on the next start.

settings.jsonTheme pick, fonts, overrides

Merged key by key, never overwritten. Writes go through writeTextFile(path, text, expected), so an edit you make by hand at the same moment isn't lost.

layout.setGlass and frames

Opacity, background and pane frames live only on layouts. Herdr's own layouts refuse all but the background, so the Glass tab first makes your own copy of the layout. The translucency sits on the rounded pane card, not the terminal, so corners stay clean.

backgrounds/studio-frost.jpgFrosted wallpaper

Made by one Core Image call through exec("osascript", …). Rebuilt only when the wallpaper path changes.

  • Opening it: one key (⌃⇧Y proposed, to check against keys.json) and a palette entry, both running mod.open. It opens as a kept, draggable kind: "window" overlay, so it stays put while you look at the real window.
  • Live preview: the Studio's own swatches update immediately. File writes are debounced to 120 ms while a slider is dragged, and the app redraws within a second.
  • Safety: before its first write, the Studio snapshots settings.json and the layout's look to data/theme-studio/. Revert restores that snapshot. After each write it reads settings.error / layout.error and shows any problem as a toast. Herdr's ⌃⌥⇧Esc reset still works as the last resort.
  • Presets: about a dozen permissively licensed palettes ship inside the mod: Tokyo Night, Catppuccin Mocha and Latte, Gruvbox, Nord, Rosé Pine, Dracula, Kanagawa, Everforest, Solarized, One Light. They're copied into themes/ when first used.
  • Sharing: Export writes a folder in the herdr.dev/mods format, with a RECIPE.md and a preview.png taken with herdr-app shot.

Build plan

  1. Spike, half a day. Prove three open questions before writing UI: does layout.set on the shipped main layout accept terminal_opacity, background and pane; do #rrggbbaa chrome colors let a background image show through the sidebar; does the osascript Core Image blur run unprompted on this Mac?
  2. Themes, Colors, Type. The gallery, the token editor with contrast checks, font pickers. The lib.js self-check passes and herdr-app check passes.
  3. Glass. Opacity, backgrounds, frosted wallpaper and pane frames, plus snapshot and Revert.
  4. Library. Saved looks, import from Ghostty, kitty and Alacritty, export for herdr.dev.

Left out: theming the herdr TUI, which uses a different config and plugin system and could reuse the same palettes later. iTerm .itermcolors import (plist), until someone asks for it. Per-block looks, which Herdr says are coming but aren't there today.

Decided

  • Called Theme Studio, opened with ⌃⇧Y, which isn't bound in keys.json.
  • Frosted wallpaper ships in v1, labelled wallpaper-only.
  • Desktop only, with no sync to the TUI.
  • Real window blur: add our use case to herdr-app#190 instead of opening a duplicate.
